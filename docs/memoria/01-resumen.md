# Resumen

Este proyecto desarrolla un prototipo de gestión de citas para Clandestino, una barbería de un solo barbero que trabaja únicamente con cita previa y con clientes que entran por invitación. La barbería ya usa una aplicación web propia, y el proyecto reconstruye su núcleo como aplicación nativa de Android escrita en Java, con una API REST propia, también en Java, y una base de datos MySQL. El análisis de siete aplicaciones de reserva del mercado, entre ellas Booksy, Fresha y Treatwell, muestra que ninguna combina el acceso cerrado por invitación, el cupo diario configurable y la ausencia de cuotas o comisiones, que son las tres reglas que necesita este negocio. El trabajo siguió un ciclo de vida incremental con prácticas de Scrum adaptadas a una sola persona, en cuatro etapas: inicio, diseño, desarrollo y cierre. En la fase de diseño se elaboraron el modelo entidad-relación de cinco tablas, diez casos de uso, treinta requisitos funcionales, los mockups de las pantallas y los diagramas de clases y de secuencia. La API se programó sin frameworks, sobre el servidor HTTP del JDK, con contraseñas protegidas mediante PBKDF2, tokens JWT firmados con HMAC, límite de intentos de acceso y consultas parametrizadas. La app sigue el patrón MVVM, hace todas las peticiones de red en hilos secundarios y guarda el token cifrado con una clave del Android Keystore. El punto más delicado del sistema era evitar que dos clientes que piden cita a la vez superen el cupo del día. La base de datos impide por sí misma dos citas activas a la misma hora gracias a una columna generada con índice único, pero ningún índice puede contar las citas de un día, de modo que el servicio de citas protege esa operación con un bloqueo por fecha y una única transacción. Una prueba con cinco hilos concurrentes demuestra el problema y su solución: sin el bloqueo se crean cinco citas en un día con cupo de una, y con él solo se crea una. El prototipo supera 88 pruebas automáticas en la API, 25 en la app y 21 sobre el esquema de la base de datos, y se ha recorrido el flujo completo de cliente y barbero en el emulador de Android. Como limitaciones quedan la falta de cifrado HTTPS, la ausencia de avisos al cliente y algunas comprobaciones de rendimiento previstas que no se llegaron a hacer, que se proponen como trabajo futuro.

**Palabras clave:** Android, API REST, gestión de citas, concurrencia, MySQL.
