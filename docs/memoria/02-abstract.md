# Abstract

What I want to show in this project is how I looked for a solution to a problem in my own work. I cut hair at home and could not find a booking app that worked for me, because the apps on the market are built for businesses with a high-street shop and the best known ones, such as Booksy, work as a marketplace where my clients would also see other barbershops. Clandestino is the app I have built for my own use and for other barbers who work from home and want to keep their own clients loyal instead of sending them to a marketplace. Access is by invitation only, the barber sets the daily limit and the interface keeps to the essentials. It is a native Android app in Java, backed by a custom REST API and a MySQL database, that rebuilds the core of the web version I already used. A review of seven booking apps shows that none of them combines invitation-only access, a configurable daily limit and no fees or commissions. I followed an incremental life cycle with Scrum practices. The design stage produced a five-table entity-relationship model, ten use cases, thirty functional requirements, screen mockups, and class and sequence diagrams. I wrote the API without frameworks, on top of the HTTP server included in the JDK, with PBKDF2 password hashing, HMAC-signed JWT tokens, login attempt limiting and parameterised queries. The app follows the MVVM pattern, runs every network request on a background thread and stores the session token encrypted with an Android Keystore key. The hardest part was making sure that two clients booking at the same time cannot exceed the daily limit. The database blocks two active appointments at the same time slot through a generated column with a unique index, but no index can count the appointments of a day, so the appointment service protects that operation with a per-date lock and a single transaction. A test with five threads proves it, since without the lock five appointments are created on a day limited to one and with it only one. The prototype passes 97 automated tests in the API, 26 in the app and 21 on the database schema, and I have run the full client and barber flow on the Android emulator. I also completed one feature from the second phase, which lets the barber add an appointment by hand for clients who phone in. HTTPS and client notifications are left as future work.

**Keywords:** Android, REST API, appointment scheduling, concurrency, MySQL.
