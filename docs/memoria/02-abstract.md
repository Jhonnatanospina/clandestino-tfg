# Abstract

This project builds an appointment management prototype for Clandestino, a one-person barbershop that works by appointment only and accepts new clients by invitation. The shop already runs its own web application, and the project rebuilds its core as a native Android app written in Java, backed by a custom Java REST API and a MySQL database. A review of seven booking apps on the market, including Booksy, Fresha and Treatwell, shows that none of them combines invitation-only access, a configurable daily limit and no fees or commissions, which are the three rules this business needs. The work followed an incremental life cycle with Scrum practices adapted to a single developer, in four stages: start, design, development and closure. The design stage produced a five-table entity-relationship model, ten use cases, thirty functional requirements, screen mockups, and class and sequence diagrams. The API was written without frameworks, on top of the HTTP server included in the JDK, with PBKDF2 password hashing, HMAC-signed JWT tokens, login attempt limiting and parameterised queries. The app follows the MVVM pattern, runs every network request on a background thread and stores the session token encrypted with an Android Keystore key. The hardest part of the system was making sure that two clients booking at the same time cannot exceed the daily limit. The database itself blocks two active appointments at the same time slot through a generated column with a unique index, but no index can count the appointments of a day, so the appointment service protects that operation with a per-date lock and a single transaction. A test with five concurrent threads shows both the problem and the fix: without the lock, five appointments are created on a day limited to one, and with it only one is created. The prototype passes 88 automated tests in the API, 25 in the app and 21 on the database schema, and the full client and barber flow has been run on the Android emulator. Its limitations are the lack of HTTPS, the absence of client notifications and some planned performance checks that were not carried out, all of which are proposed as future work.

**Keywords:** Android, REST API, appointment scheduling, concurrency, MySQL.
